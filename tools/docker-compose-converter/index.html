关于 Docker Run 转 Compose

        
工具在浏览器本地把 shell 命令拆分为结构化参数，再由 js-yaml 生成 Compose YAML。支持 --name、-p、-v、-e、--env-file、--network、--restart、--workdir、--user、--entrypoint、--hostname、--label、--add-host、--dns、--device、--cap-add、--cap-drop、--memory、--cpus、--shm-size、--privileged、--read-only、-i、-t 和容器启动命令等常见选项。转换后建议运行 docker compose config 做最终校验。

        
常见问题

        
为什么没有生成 version 字段？
现代 Docker Compose Specification 已不要求 version，Compose v2 会忽略旧版 version 字段并给出提示，因此工具直接输出 services。

        
-d 和 --rm 转换到哪里了？
-d 是 docker run 客户端的启动方式，不属于服务配置；--rm 是一次性容器退出后的清理行为，在长期运行的 Compose 服务中没有完全等价配置，工具会提示但不会写入 YAML。

        
生成后可以直接启动吗？
常见命令通常可以。复杂的 --mount、GPU、健康检查或平台特定参数仍应人工核对，并先用 docker compose config 检查语法与变量插值结果。
